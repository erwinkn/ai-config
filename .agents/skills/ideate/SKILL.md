# Ideate

A distinct ideation pipeline: ground the opportunity, diverge, assess, then hand promising directions back. It is one cohesive skill, not an additional layer.

## Assignment

designer; scout for grounding; reviewer only when candidate evaluation benefits from independence.

Use the named agent definition for substantive delegated work. If you are already its assigned worker, execute this procedure directly; do not dispatch yourself again. Preserve the caller's endpoint and return mode. Read [shared rules](../principles/references/rules.md) and the relevant [principles](../principles/SKILL.md).

## Procedure

1. Identify the user, problem, opportunities, constraints, and the kind of ideas sought. Research only enough to ground useful generation.

2. Generate genuinely different directions before committing to one. Use swarm compare when independent generation is worth its cost.

3. Evaluate against declared user and project criteria, separating evidence from speculation. Keep promising minority ideas rather than forcing premature consensus.

4. Present a small concrete set of directions with reasons, limitations, and the next experiment. Hand a selected idea to discover or design only when the user chooses to develop it.

## Rules

- Do not reopen settled requirements in a running delivery task under the label of ideation.
- An idea is not approval to implement or publish.
- Do not confuse variation in wording with variation in the underlying proposal.

## Complete when

A useful grounded set of options or a chosen direction is returned; uncertainties remain explicit.

Return or save research, decision, plan as needed under [artifact conventions](../../ARTIFACTS.md).

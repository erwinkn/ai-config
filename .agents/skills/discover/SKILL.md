# Discover

Develop an unsettled idea into a usable decision or plan. New-idea generation lives in ideate; ordinary architectural alternatives stay in design.

## Assignment

lead.

Use the named agent definition for substantive delegated work. If you are already its assigned worker, execute this procedure directly; do not dispatch yourself again. Preserve the caller's endpoint and return mode. Read [shared rules](../principles/references/rules.md) and the relevant [principles](../principles/SKILL.md).

## Procedure

1. Read existing intent and research. Use ideate only when new options or opportunities are requested or needed; use clarify for unresolved human decisions, not facts the environment can answer.

2. Use model for precise domain language and design for the chosen direction’s architecture and alternatives. alternatives is an optional explicitly requested rethink of an existing system, not a universal phase.

3. Use prototype for consequential questions that require an experiment or concrete user interaction.

4. Use plan to capture specification and implementation sequence together. Stop at the requested discovery/planning result until execution is authorized.

## Rules

- A ready build request goes to deliver, not another discovery loop.
- For a huge uncertain effort, keep a decision frontier in the plan; do not prewrite a fictional complete backlog.

## Complete when

The next decision is settled or a plan is ready, with remaining uncertainty visible.

## Decision map

For work too uncertain to specify end-to-end, keep a small map of the destination, resolved decisions, precise open questions with blockers, and still-vague areas. Resolve the currently answerable frontier through research, clarify, design, or prototype. A human judgment is not delegated to an agent pretending to be the human. When decisions make implementation possible, plan produces executable units. Do not maintain a second redundant store of every ticket’s details.

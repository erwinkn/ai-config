# Compound

Model-invokable improvement of the Markdown stack. Real use is the main evidence. Direct scoped edit requests are already approval; inferred patterns remain proposals until accepted.

## Assignment

lead.

Use the named agent definition for substantive delegated work. If you are already its assigned worker, execute this procedure directly; do not dispatch yourself again. Preserve the caller's endpoint and return mode. Read [shared rules](../principles/references/rules.md) and the relevant [principles](../principles/SKILL.md).

## Procedure

1. Inspect the relevant feedback, current instructions, and available run evidence. Separate explicit user decisions from inferred recurring patterns or isolated incidents.

2. Choose the smallest correct home: principle, rule, skill, playbook, role, project knowledge through learn, or no lasting change.

3. For an explicit instruction to change reusable guidance, apply that focused change without a second approval prompt. For an inferred improvement, present the exact proposal and expected effect before editing active guidance.

4. Remove or revise contradicted and duplicated instructions rather than append exceptions. Preserve intended human checkpoints, named boundaries, and a reversible change record.

5. Check links, invocation settings, assignments, and representative examples. Use evaluate only when a comparison is helpful. State which effects were observed and which remain hypotheses.

## Rules

- Model invocation enables discovery and orchestration; it does not grant permission for unrequested persistent writes.
- A direct "make this a rule" is a concrete authorization, not a reason to ask whether to run compound.
- Project facts and domain-specific lessons belong in project knowledge unless the user explicitly wants a broader rule.
- An explicit stylistic or operational preference can be recorded as the user’s choice without pretending it was empirically validated.

## Complete when

An authorized focused instruction revision is recorded and checked, or a precise unapproved proposal is returned without changing active behavior.

## Feedback

Inspect explicit corrections and real run evidence. Separate a direct user preference, a recurring instruction failure, a trigger/discoverability failure, a missing project mechanism, and a one-off. compound can be model-invoked to analyze and propose any of them. Apply active stack edits immediately when the user explicitly requested the specific change; do not ask again. An inferred edit waits for approval unless covered by a scoped standing grant. Record provenance and expected effect, remove conflicting guidance, and keep project learning in learn.

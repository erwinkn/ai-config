# Decomposition

Separate decisions still to resolve from implementation tasks ready to execute. Prefer narrow end-to-end behavior slices with real blocking edges; avoid horizontal tickets that produce no independently useful result. A task includes its goal, owned scope, inputs, acceptance evidence, and dependencies. Size by what a fresh agent can understand and verify, not a fixed token count. Mechanical wide migrations may require expand–migrate–contract or an explicitly shared integration branch. Publish tracker items only with the requested authority.

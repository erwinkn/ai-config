# Prototype

Produce an instrument for a decision, not a low-quality production feature.

## Assignment

implementer, with designer framing and verifier checking.

Use the named agent definition for substantive delegated work. If you are already its assigned worker, execute this procedure directly; do not dispatch yourself again. Preserve the caller's endpoint and return mode. Read [shared rules](../principles/references/rules.md) and the relevant [principles](../principles/SKILL.md).

## Procedure

1. Name the question and the dimension that must be real.

2. Build the smallest isolated artifact that can answer it. Keep unrelated infrastructure and polish cheap.

3. Exercise the experiment and compare alternatives under the same relevant conditions.

4. Record the observation and any human decision; pass the finding, not accidental prototype architecture, to planning.

## Rules

- Do not fake the tested dimension. Visual finish matters when finish is the question; real interaction matters when behavior is the question.
- Do not treat agent taste as human acceptance.
- Mark and preserve useful prototype evidence; do not silently ship prototype code.

## Complete when

The experiment produced decision-relevant evidence, or its inability to do so is clear.

Return or save decision, evidence, change as needed under [artifact conventions](../../ARTIFACTS.md).

## Experiments

For a state/logic question, make the transitions observable and runnable. For a visual question, use sufficient finish and realistic density to judge it. For timing or integration, execute the relevant work instead of mocking away the uncertainty. Keep unrelated dimensions cheap. Record what was observed separately from what the human chose, and retain the useful prototype or evidence without treating it as production code.

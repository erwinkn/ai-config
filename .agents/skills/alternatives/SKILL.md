# Alternatives

An optional standalone rethink entry point. It examines a fixed existing system without assuming that another design should replace it.

## Assignment

designer; analyst for existing-system understanding; reviewer for independent comparison.

Use the named agent definition for substantive delegated work. If you are already its assigned worker, execute this procedure directly; do not dispatch yourself again. Preserve the caller's endpoint and return mode. Read [shared rules](../principles/references/rules.md) and the relevant [principles](../principles/SKILL.md).

## Procedure

1. Identify the existing system, the dissatisfaction or new constraint, the requirements to preserve, and any freedom explicitly granted.

2. Use research to understand the present mechanism and why it exists; make current design the baseline candidate.

3. Develop structurally distinct alternatives using design and, when useful, swarm compare. Include migration and operational costs, not just a nicer final diagram.

4. Return a comparative recommendation, confidence limits, and the cheapest discriminating prototype. A recommendation to retain the current design is valid.

## Rules

- Report-only by default; does not authorize rewriting the system.
- Do not strip compatibility or operational requirements to make a replacement look simpler.
- Do not run automatically for every architectural decision.

## Complete when

Credible alternatives are compared with the actual baseline and a supported next decision is offered.

Return or save research, decision as needed under [artifact conventions](../../ARTIFACTS.md).

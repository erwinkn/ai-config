# Multi-unit

A large effort uses the same deliver playbook with a durable plan. Keep unresolved decisions separate from ready implementation units. Work only the ready frontier; convey upstream decisions and actual artifacts to dependent workers. Prefer independently verifiable units, usually vertical slices. A shared contract can be a prerequisite rather than duplicated by workers. Integrate completed units during the effort, not solely at the end. Keep the canonical decision log throughout the work and checkpoint before losing context. Independent PRs branch from the appropriate base; dependent PRs use the project’s supported stack conventions. Only lead changes canonical topology. Do not create a custom scheduler, daemon, state database, cloud hierarchy, or event engine. Every final PR receives the relevant audit of its decisions and proof; use a clearly scoped view when one program log covers multiple PRs. An execution grant defaults to the merge-ready tail for each deliverable, never automatic landing.

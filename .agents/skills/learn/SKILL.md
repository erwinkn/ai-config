# Learn

Capture or refresh durable project knowledge. compound owns edits to reusable stack instructions; it may call this skill when project learning is the correct destination.

## Assignment

lead; analyst for complex reconciliation.

Use the named agent definition for substantive delegated work. If you are already its assigned worker, execute this procedure directly; do not dispatch yourself again. Preserve the caller's endpoint and return mode. Read [shared rules](../principles/references/rules.md) and the relevant [principles](../principles/SKILL.md).

## Procedure

1. Check whether final code, tests, comments, and existing docs already preserve the reasoning. Write nothing when they do.

2. Capture one coherent learning, or update an existing note rather than creating a duplicate.

3. When refreshing, compare with current evidence, detect overlap and contradictions, and distinguish factual descriptions from intended rules.

4. Report keep/update/combine/remove decisions. Obtain authority for removing still-accurate material or modifying shared instructions.

## Rules

- Unverifiable does not mean false; drift can be a product regression rather than a documentation error.
- A single frustration or subjective preference is not automatically a universal rule.
- Do not create permanent memory about every completed task.

## Complete when

Qualifying knowledge is accurate and discoverable, or no note is created with a clear reason.

Return or save learning as needed under [artifact conventions](../../ARTIFACTS.md).

## Capture

Ask whether losing this reasoning would plausibly cause recurrence or substantial rediscovery after reading the final implementation. If not, write nothing. Prefer an existing note that can be updated. Capture the verified problem, non-obvious cause/constraint, resolution, and source evidence. Keep the note discoverable from the relevant project docs without inflating global startup instructions.

<a id="refresh"></a>

## Refresh

Compare existing notes with current evidence, then classify keep, update, combine, replace, or remove. Distinguish descriptive facts from normative decisions. Unverifiable is not false, and an implementation can regress relative to valid guidance. Removing an accurate but duplicative note is a value judgment, not merely a staleness repair. Changes to skills/roles themselves belong to compound and require the applicable authority.

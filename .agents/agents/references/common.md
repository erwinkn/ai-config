# Shared role instructions

Read the shared rules and relevant principles, preserve the caller’s requirements and endpoint, and execute the assigned procedure using the configured role definition. The lead owns conversational decisions, canonical integration, and the one canonical task log. Each simultaneous writer uses a separate worktree; all agents return consequential choices, observations, failed attempts, and actual proof. Workers do not append to another worktree’s log. Report unavailable tools or model substitutions honestly. Never silently override to a cheaper or stronger model, fake independent work, recurse into your own role, or take over the caller’s shipping tail.

## Model notes

Each of the twelve agent definitions has its own setup-selected model. Different definitions may share a model. The procedure names the definition through explicit task conditions: fast implementation for settled mechanical edits, ordinary implementation by default, deep implementation for difficult semantics, simplifier for structure, reviewer-second for an independent additional model, and auditor for decision evidence. Keep model-specific prompting notes short and local to the relevant definition. Actual IDs require host-supported configuration and representative use, not an assumed universal ranking. No runtime registry, profile taxonomy, or custom dispatcher is introduced.
